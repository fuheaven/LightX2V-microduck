## 渲染问题与当前选择

最初的 CUDA 镜像缺少 NVIDIA EGL vendor JSON，实际使用 llvmpipe；同步取图使仿真只有约 0.49×。补齐 vendor 选择后确认渲染设备为 NVIDIA H200，但该服务器的 `580.95.05` 驱动在 EGL 与 CUDA 并用时再次出现长时间取图卡顿，测试已取消，进程退出后 GPU 内存释放。

因此采用已有的后台 OSMesa 快照路线维持物理时钟，保留真实的相机时间戳。NVIDIA EGL 作为显式可选配置保留，不能宣称已在当前 H200 上通过连续运行。未修改主机驱动、重置 GPU 或操作其他人的任务。

下一步优化应分别关注相机延迟、模型推理和动作新鲜度；单纯提高页面刷新频率无法解决站立回退。新增同卡/分卡渲染或远程渲染部署时，应记录新配置并复测，不能沿用展厅的历史分数。
