浏览器使用 Chrome 的 DevTools Protocol 实际操作和截图，没有以静态 HTML 或构建成功替代交互验证。测试中发现并修正了手机按钮挤压、favicon 缺失、无训练曲线时的 404、训练张量维度和原生推理设备初始化问题。

持续访问检查还发现，初版直接在异步请求中提交 SQLite 事务会卡住网页事件循环。线程栈指向 `Store.connect` 的 `commit` 和连接关闭；并发队列探测在 720 次请求内出现 36 次超时。单独切换 Python/SQLite 运行环境、以及只串行化短连接，都不足以解决问题。最终改为单 Web 进程持有长期 WAL 连接、短事务串行执行、退出时关闭连接，避免每次心跳触发最后连接的关闭/检查点；队列读写、模型校验及技能包处理均在线程池执行。修复后的 **6,000 次混合读写请求零错误**，12 路并发用时 95.40 秒，最慢请求 1.31 秒；随后健康检查约 1ms。原始结果为 `web-queue-concurrency.json`，不能据此声称无限时长稳定性。

服务保留 `SIGUSR1` 线程栈诊断，并拒绝启动已知存在 Unix 锁死问题的 SQLite 3.51.0/3.51.1；该版本问题见 [SQLite 官方发布说明](https://sqlite.org/releaselog/3_51_3.html)。该依赖问题是单独的防护检查，并不作为上述现象的唯一根因结论。当前本机 Web 环境使用独立 Python 3.12 / SQLite 3.53.1。

## H200 完整 FastWAM 检查

在单张 H200 的独立诊断容器中，从已发布 MicroDuck 权重初始化，扩展为 176D。使用真实 MuJoCo 传感器记录进行一次完整模型前后向、参数更新、保存、重载和原生推理。

| 指标 | 结果 |
|---|---:|
| 有限训练 loss | 0.8949611 |
| 梯度范数（裁剪前） | 15.1875 |
| 模型重载前后最大绝对差 | 0 |
| 参考实现与 LightX2V 输出最大绝对差 | 0 |
| 输出 | 32×5 |
| 此进程峰值 CUDA allocated memory | 30.88 GiB |

随后验证了优化关闭/开启时的固定输入、变化的图像与状态、变化的指令、会话重置，动作最大绝对差均为 0。3 次预热后推理的诊断 p95 分别约为 **523ms / 184ms**。样本量很小，**不作为正式性能验收或闭环能力收益的结论**。

实现诊断总计占用约 **0.316 H200 GPU 小时**，包括失败后修正的检查。诊断容器均已退出。没有运行新的完整技能训练轮次，也没有把单步诊断权重发布为可用技能。

验证完成后已清理本次产生的两份临时单步诊断权重，共 24.09 GB；保留配置、摘要及检查报告，原发布权重与训练结果未改动。

H200 检查使用此前经过验证的 FastWAM 容器派生环境，底层为固定 PyTorch 2.7.1/cu128。完整 `Worker.Dockerfile` 在一台全新机器上的从零构建**尚未完成验收**；Web 镜像的构建和运行已实际验证。两者不能混为“所有部署环境均已通过”。

## 当前服务

新工作室使用独立的 8771 端口。现有部署已连接本机 CPU 运行器，并使用 NVIDIA EGL 渲染。短时真实测试运行倍率约 **1.00×**；软件渲染对照约 **0.13×**。它们验证持续物理运行和画面通路，不证明任务成功。

Web 和 CPU 运行器由独立用户服务管理。旧 8770 展厅、8768 训练监控及其链接保留。

**当前网页队列尚未连接 H200 GPU worker。** 新页面可以查看历史录像、编辑场景、运行预览和规则策略。FastWAM 历史实时运行、GPU 训练等请求会等待匹配的 GPU 运行器；需要按部署文档配置相同源码、镜像标识和共享制品目录后执行。H200 上的诊断通过不等于该运行器已经接入网页队列。
