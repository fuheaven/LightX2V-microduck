## 实测结果

- 官方本体摘要：`c84586273415452a4f4b87dfb525506cc31938b84d1c07b69ee4d0512e179c29`，15 个 body，`official_bam`。
- 家具的 MuJoCo 几何中心与共享配方计算值最大误差：`1.11e-16 m`。
- 固定 120 tick 动作序列中，启用和关闭观察者导出后的 `qpos` 最大差：`0`。
- 真实浏览器读取并应用 MuJoCo 位姿后，Three.js 世界坐标与导出坐标最大误差：`0 m`，满足 `1e-4 m` 目标。
- 一次 45 秒的规则策略连续仿真：2,250 个控制 tick，墙钟 45.003 秒，实际倍率 `0.99994×`，GPU 用量为 0。**该寻球任务超时失败**，这项结果仅证明连续运行链路，不能当作技能通过。
- 带家具环境导出、导入独立临时工作区后，布局和资产摘要保持完全一致；未复制权重或验收结论。
- 三个实际 MuJoCo 近目标停稳案例（训练/验证/测试各一个）通过记录与数据审计；loader 可读取 RGB `[4,256,256,3]`、状态 `[4,176]`、动作 `[32,5]`。这些案例检查停稳、记录和训练输入连接，**不证明导航泛化，也不替代教师 100 条门槛**。
- 原始头部录像的 5 秒片段确定性转换为 124 帧、24fps、960×544；实际时长 5.167 秒，逐帧时间映射及文件检查通过，原录像 SHA256 未改变。该输出是模型参考输入，**不是生成录像**。
- Studio 两个测试文件共 33 项通过；前端 TypeScript/Vite 构建通过。新模块 Ruff 检查通过，前端运行依赖审计无已知漏洞。

## 运行与恢复

浏览器在同一实时实验中经历 Web 退出和重连：退出前 tick 330，失联后停留在 tick 490 并显示“画面冻结”，重连后接上 tick 995；几何误差持续为 0，头部相机恢复为原始 256 像素输入，运行器和 run ID 不变，没有重复任务。随后点击“取消作业”，作业正确进入 `cancelled`。Web 长连接退出限制为 3 秒（实测进程退出约 3.50 秒），避免旧进程长期持有 SQLite 连接。

GPU 排队回归测试验证：训练作业占用某个 UUID 时，同 UUID 视频运行器不能领取第二个作业；结束后才能领取。运行器还使用共享目录的 OS 文件锁，并将锁描述符传给计算子进程。**物理 GPU 上的并发压力测试尚未进行**，当前测试不代表显存/吞吐验收。

视频审核测试使用明确的单元测试文件夹具，检查“不确定不可标通过”、文件变更使原审核失效、审核历史追加、导出和任务结果隔离；它不提供 H3 图像质量证据。

## 构建与可复核材料

视频镜像已实际构建，并在无网络容器内成功导入 Studio worker、Diffusers ModularPipeline、MiniMaxH3VideoReference 和 encode_video；容器与工作区源码摘要一致。当前构建主机仅有 classic Docker，因此验证使用与 `.dockerignore` 等价的显式白名单上下文；正式部署使用 Compose v2 / BuildKit。镜像构建增加源码导入检查，缺失源码时直接失败。

无模型的运行器正确返回“H3 本地模型未配置或缺少 modular_model_index.json”，没有占位生成结果。当前 Studio 也未配置自然语言布局服务，手工编辑仍然可用。H200 的网络端口可达，但本执行环境的非交互 SSH 认证未通过；未启动远程模型进程。
